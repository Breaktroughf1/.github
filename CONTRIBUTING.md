# Contributing to BreaktroughF1 open source

Thanks for helping. Each project has its own contributing guide with build and test steps; this page covers what applies everywhere.

1. **Start a conversation first** for anything bigger than a typo: open a discussion in [Ideas](https://github.com/orgs/Breaktroughf1/discussions/categories/ideas) or comment on an issue, so we can agree on the approach before you write code.
2. **Fork, branch, and keep pull requests small.** One change per pull request, with tests and a changelog entry where the project has one.
3. **Run the project's checks locally** (format, analyze, tests) before you push. CI runs the same checks.
4. **Never include secrets**, OTP seeds or personal data in code, tests or screenshots.
5. **Security issues are reported privately**, never in a pull request. See [SUPPORT.md](SUPPORT.md).

By contributing you agree that your work is released under the project's licence, and you agree to follow our [code of conduct](CODE_OF_CONDUCT.md).
